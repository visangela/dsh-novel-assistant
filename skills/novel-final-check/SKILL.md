# 阶段 10 · 完稿检查与 bug 修正

目标：把「能读」修到「可以交出去」。**分三步、分批改，绝不一次性重写全书。**

## 一、触发与范围

- 触发：最后一卷最后一章写完且 `novel-mid-check` 已过（主动）；用户说「准备定稿」「全书通检」「查前后矛盾」「看看有没有 AI 味」，或准备交平台、交编辑、做实体书（被动）。
- 范围：全书正文 + `bible/` 全部设定库。**正文还没写完不要跑本技能**，缺章时报告只能标「阶段性检查」，结论不作定稿依据。

### 执行顺序

三步按 **B → A → C** 跑，虽然报告按 A/B/C 编号：

| 顺序 | 部分 | 理由 |
| --- | --- | --- |
| 1 | B 逻辑 bug | 先修事实层，避免改写句子后 bug 定位失效 |
| 2 | A AI 味 | 在事实正确的文本上改文风，改完不会再动情节 |
| 3 | C 阅读体验 | 最后看整体节奏，此时文本已稳定 |

全书超过 30 章时按卷分批读，每卷只精读 2 章、其余用 `grep` 定点抽查；不要把整本书读进一次上下文。

## 二、A. AI 味检测

「AI 味」在这里指**文本的机械感**：读起来顺、但没有人在说话。逐项查，每项给命中位置与次数。

| 检查项 | 怎么判断 | 典型病灶 |
| --- | --- | --- |
| 句式过于均匀 | 连续 5 句以上同为主谓宾；句长集中在 15–25 字 | 每句都在交代，没有短句打断、没有长句铺开 |
| 过度解释心理 | 每段都直接说情绪（「她感到一阵悲伤」） | 用情绪标签代替动作、生理反应、物件 |
| 空泛比喻 | 比喻不指向具体经验（「像深渊」「如同花朵」） | 换成能被拍到的细节 |
| 段落工整对仗 | 三段排比、每段首句同结构、每段一样长 | 像报告，不像叙事 |
| 人物替作者讲道理 | 角色突然说出主题句、人生总结 | 台词变论文，人物失去欲望 |
| 重复口头禅与转场句 | 「不知过了多久」「空气仿佛凝固」「与此同时」 | 用 `grep` 数次数 |
| 章末总结升华 | 每章最后一句都在抒情或点题 | 读者被反复告知该感动 |

**三组对照示例**（写报告时按同样格式给，每组注明改法与代价）：

**示例 1 · 句式均匀 + 章末升华**

> 原文：她走进房间，看见桌上的信。她拿起信，手在发抖。她读完信，眼泪流了下来。她终于明白，一切都结束了。

> 改写：桌上有封信。她认得那个字迹——去年冬天，他就是用这支笔给她写欠条的。信纸边缘卷了，像被人攥过。她读到第三行就停了，把纸按回桌面，掌心压着，好像这样就能让那行字退回去。

改法：拆句、给具体物件、把「明白」换成动作。代价：字数 +40，节奏变慢，适合章中不适合章末。

**示例 2 · 过度解释心理**

> 原文：他感到很愤怒，因为对方又一次欺骗了他。他强忍着怒火，告诉自己必须冷静。

> 改写：他笑了一下。对方还在说，说得很顺，连停顿都恰到好处。他把茶杯放回桌上，杯底磕出一声脆响，才发现自己用了多大力气。

改法：删情绪标签，用动作与身体反应承载。代价：读者需要多读一遍才懂，牺牲一点直给。

**示例 3 · 空泛比喻 + 人物讲道理**

> 原文：他的眼神像深渊一样深不可测。他缓缓说道：「人这一生，总要学会放下。」

> 改写：他看着她，眼睛没什么表情，只是很久没眨。「钥匙留下。」他说。

改法：比喻换成可观察的细节；道理换成具体诉求，主题让读者自己得出。代价：这句话不再「有分量」，但人物立住了。

## 三、B. 逻辑 bug 修正

用 `grep` 工具或 `bash` 抽查，每项都要贴命令与命中结果：

| 查什么 | 怎么查 | 看什么 |
| --- | --- | --- |
| 人名一致 | `grep -rn "林砚" novel-project/chapters \| wc -l`，再 `grep -rn "林彦\|林岩"` | 错字、别名混用、称呼随关系变化是否有交代 |
| 能力越界 | `grep -rn "剑意\|灵力\|境界" novel-project/chapters` | 是否超出 `architecture.md` 的上限，代价有没有付 |
| 时间词 | `grep -rn "次日\|三日后\|半个月\|入夜\|天亮"` | 逐条对 `timeline.md`，章节间隔是否够路程 |
| 地点 | `grep -rn "寒山\|药王谷\|州府"` | 同一章内是否瞬移，赶路是否被省略到不可能 |
| 伏笔编号 | `grep -rn "F0" novel-project/chapters` | 与 `foreshadowing.md` 表比对，正文提到的编号是否存在 |
| 数字 | 银两、年龄、人数、距离 | 前后是否一致，尤其是「十年」「三百里」这类大数 |

三项专项核对：

1. **`timeline.md` 与正文核对**：把正文里所有明确时间点抽出来，与表逐条比。冲突时以正文为准改表，或以表为准改正文——由用户定，不要自己选。
2. **伏笔清算**：列出「未回收」「逾期」（预定回收章已过）两组编号；未回收的判断是「留到续集」还是「作者忘了」，逾期的必须处理或改预定章。
3. **结局回收**：`outline.md` 的「全书要回答的问题」是否被回答；主角弧光的终点是否兑现（对照小传的「关键选择」）；主要伏笔回收率是否 ≥80%，未回收的写明为什么可以留。

## 四、C. 阅读体验

- **开篇三章**：第一章前 500 字有没有人物欲望与麻烦；前三章是否给出「继续读的理由」；有没有大段设定说明。
- **每卷开头**：新卷第一段是否重新建立时间、地点、目标；有没有「上一卷回顾」式复述。
- **章末钩子密度**：统计每章最后一段的类型（悬念/反转/决定/坏消息/情绪收束），连续 3 章同类型或连续 3 章无钩子就是问题。
- **重复场景**：同类场面（谈判、追杀、疗伤、回忆）是否超过 3 次且功能相同；重复的用「差异表」看每次多了什么。
- **拖沓段**：整段只有情绪没有推进、对话在原地打转、走路与吃饭被逐动作描写。

用 `bash` 出基础数据（报告里必须贴这三行结果）：

```bash
# 章数、总字数、平均章长（按字符计，适合中文）
find novel-project/chapters -name 'ch-*.md' -print0 \
  | xargs -0 wc -m \
  | awk 'NF==2 && $2!="total"{n++; s+=$1} END{printf "章数 %d｜总字数 %d｜平均 %.0f 字/章\n", n, s, s/n}'

# 每卷字数，看卷间是否失衡
for d in novel-project/chapters/vol-*; do
  printf "%s " "$(basename "$d")"
  find "$d" -name 'ch-*.md' -print0 | xargs -0 cat | wc -m
done

# 最长的 5 章，定位拖沓
find novel-project/chapters -name 'ch-*.md' -print0 | xargs -0 wc -m \
  | grep -v total | sort -rn | head -5
```

## 五、产出两个文件

**`reviews/final-check.md`**：问题全表。

```markdown
# 全书完稿检查

- 检查日期：YYYY-MM-DD｜全书 N 章 / N 万字
- 结论：blocker X 项、high Y 项、medium Z 项、low W 项

## 一、问题表
| 编号 | 等级 | 位置 | 证据 | 问题 | 修法 | 工作量 |
| --- | --- | --- | --- | --- | --- | --- |
| A01 | blocker | ch047 | 「他早知密道」 | 与 ch009 信息表冲突 | 改判断依据为脚印 | 10 分钟 |

## 二、A 部分：AI 味（含 3 组原文→改写对照）
## 三、B 部分：逻辑 bug 与伏笔清算
## 四、C 部分：阅读体验与字数统计
## 五、三组交付建议
- 必须改（blocker）：……
- 建议改（high/medium）：……
- 可不改（low）：……
- 预计总工时：约 N 小时 / N 轮
```

**`reviews/final-check-fixed.md`**：修复记录，只记已关闭项与未修项。

```markdown
# 修复记录
| 编号 | 状态 | 修复章 | 改法 | 复查 | 日期 |
| --- | --- | --- | --- | --- | --- |
| A01 | 已关闭 | ch047 | 改为依据脚印推断 | 已读上下文，无新冲突 | 2026-11-08 |
| B03 | 未修 | — | 用户接受：留作续集钩子 | — | — |
```

## 六、先给范围，再问用户

先给三组与工时，再 `ask_user_question`（最多 3 问）：

1. **「这次修到哪个范围？」** 选项：只改必须改（推荐）/ 必须改 + 建议改 / 全改（含 low）。
2. **「改法偏好？」** 选项：只改句子不动情节（推荐）/ 允许小改情节 / 允许重写段落。
3. **「要不要保留改写前后对照？」** 选项：保留 3 组示例（推荐）/ 全量保留 / 不保留。

**不要一次性重写全书。** 用户要求「一次改完」时，先给分批方案（每批 ≤10 处，每批后停下汇报），说明一次改完的风险：bug 会互相覆盖、风格会断层、无法回滚。

## 七、修复执行规则

- 一批不超过 10 处，按章号从后往前改（后面的改动不影响前面的行号）。
- 每批改完 `read` 改过的段落上下文各 20 行，确认没有引入新矛盾。
- 改情节前先改 `outline.md`，再改正文；只改句子不动情节的，不用通知。
- 动过的章在 `final-check-fixed.md` 记章号与改法；blocker 必须写复查结论。
- 改完重跑 B 部分的 `grep` 抽查与 `timeline.md` 核对，确认没有修出新 bug。

## 八、质量自检清单

- [ ] 全书章数与字数已用命令统计，不是估的。
- [ ] A 部分给了 3 组原文→改写对照且各写了代价；B 部分每项有命令与命中结果，逾期伏笔已列编号。
- [ ] C 部分覆盖开篇三章、每卷开头、章末钩子、重复场景、拖沓段。
- [ ] 问题表每条有位置 + 证据 + 修法 + 工作量。
- [ ] 三组交付建议与工时已给用户，用户已选范围。
- [ ] `final-check-fixed.md` 与 `final-check.md` 编号对得上。
- [ ] 修完后重跑过抽查，没有新增冲突。

## 九、门禁

两条同时满足才算定稿：

1. **blocker 清零**：`final-check.md` 里所有 blocker 在 `final-check-fixed.md` 中为「已关闭」，且有复查结论；
2. **用户明确说定稿**（不是「差不多吧」）。

然后更新 `PROJECT.md`：阶段 10 完成、定稿日期、最终字数与章数、遗留 low 项清单、下一步。再进入阶段 11 `novel-graph`。

## 十、失败与回退

| 情况 | 处理 |
| --- | --- |
| 章节太多（>100 章）读不完 | 按卷分批出报告，`final-check.md` 用卷分节；每卷精读 2 章 + 其余 `grep` 抽查，报告写明抽查比例 |
| 判断不了是否 AI 味 | 朗读测试：读出声是否每句同调；或统计句长分布，方差过小即命中 |
| 用户不认某条「必须改」 | 保留条目但降级为「建议改」，写清理由，不删除 |
| 改完发现新 blocker | 停下，重新评估范围，不要边改边扩 |
| 用户跳过检查直接要关系图 | 提醒风险，最小跑 B 部分（blocker 级）再进 `novel-graph`，`PROJECT.md` 标「跳过完稿检查」 |

## 十一、收尾

汇报 12 行内：字数与章数、三组问题数量、必须改清单（章号 + 一句）、用户选的修复范围、预计工时。修完汇报关闭项与残留项，然后加载 `novel-graph`；若检查发现主线级问题（结局没回收、人物弧光断裂），回 `novel-workflow` 重新对阶段，不要在图谱阶段硬圆。
