# 阶段 0 · 立项

目标：用最少的问题拿到「写什么、写给谁、大概多长」，建好项目骨架，然后把用户送进阶段 1。**本阶段不写大纲，不写人物小传。**

## 一、先判断是否已有项目

- 已有 `novel-project/PROJECT.md`：读它，告诉用户当前阶段，转 `novel-workflow`。
- 目录存在但没有 `PROJECT.md`：问用户是继续旧项目还是新建；不要覆盖已有文件。
- 没有项目：再看一眼有没有现成稿件——工作区里有 `chapters/` 或大量按章命名的 `.md`，说明作者已经写了一部分，转 `novel-import`（阶段 −1），本技能不处理这种情况。
- 确实是从零开始：继续下面的立项访谈。

## 二、立项访谈（最多两轮，每轮不超过 3 个问题）

第一轮必须拿到：

1. **核心想法**：一句话说出你想写的故事（谁，想要什么，被什么挡住）。
2. **题材与读者**：古代言情 / 古言武侠 / 古言官场 / 仙侠 / 悬疑 / 都市 / 科幻……以及主要读者是谁、想要什么阅读体验（爽、虐、烧脑、治愈、震撼）。
3. **规模**：预计多少万字、分几卷、单章大约多少字。

第二轮按需补：

- 有没有想参考的作品或作者（只借结构与气质，不抄文字与情节）。
- 有没有绝对不能出现的内容（雷点、禁忌关系、BE/HE 偏好）。
- 更新节奏：日更 / 周更 / 一次性写完。

用户答不上来的项，给一个默认值并说明「可以后面再改」，不要卡住。**不要一次问超过 3 个问题。**

## 三、建目录

优先复制本技能自带的模板（技能资源里会给出 Base directory）：

```bash
mkdir -p novel-project
cp -R "<技能 Base directory>/templates/." novel-project/
```

如果看不到 Base directory，就按下面的结构手工创建空文件：

```
novel-project/
  PROJECT.md
  README.md
  bible/architecture.md
  bible/style.md
  bible/outline.md
  bible/timeline.md
  bible/foreshadowing.md
  bible/knowledge-reader.md
  bible/knowledge-protagonist.md
  bible/facts.md
  bible/digest.md
  bible/characters/_index.md
  bible/characters/_template.md
  outline/vol-01/
  chapters/vol-01/
  chapters/.versions/       改稿存档（脚本自动生成，不要手建、不要删）
  reviews/
```

模板里的 `{{...}}` 占位符要替换，不要留空占位。

## 四、填写 PROJECT.md

至少写清：书名（可暂定）、题材、一句话梗概、目标篇幅、当前阶段「0 立项 → 1 小说架构」、当前进度、下一步、创建日期。决策日志记下本轮确认的题材、读者、规模、参考作品与雷点。

「正文模型」块：通道「主代理自写」、代笔模型「不指定」、手动通道「关」、选择方式默认「试笔」、试笔结论「未试」。

立项只问**一个问题**：正文要不要在写第 1 章前试笔？选项：试笔（推荐，双段同写，你读完再定谁写）/ 直接指定模型 / 跟随默认。**不要问「你想用哪个模型写正文」**——多数人这会儿答不上来，等有细纲和样段时选择才有意义。用户选「试笔」就保留默认值；选另两项就现在填好，阶段 7 不再问。

## 五、收尾汇报

给用户不超过 8 行的汇报：

- 项目建在哪个目录；
- 已确认的题材 / 读者 / 规模 / 参考作品；
- 还缺什么（例如「主角金手指还没定」）；
- 下一步：进入阶段 1「小说架构」，会先问 5–8 个关键问题再动笔。

然后调用 `ask_user_question` 只问一个问题：「现在开始搭架构吗？」选项：开始 / 先改设定 / 我先自己想想。

用户确认后加载 `novel-architecture`。**不要在本阶段顺手写架构或大纲。**
