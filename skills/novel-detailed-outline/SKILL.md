# 阶段 6 · 细纲

目标：把 `bible/outline.md` 里「章节关键设定」的一行，展开成能直接开写的细纲。**一次只写 3–5 章**：正文会边写边改，细纲写太远一定作废。细纲解决三件事——这场戏谁想要什么、冲突怎么升级、章末拿什么勾住读者。

## 一、前置检查

1. `read novel-project/PROJECT.md`：当前阶段 6，确认当前卷、下一批章号（如第 6–8 章）、单章目标字数。
2. `read` 设定库全部：`bible/architecture.md`、`style.md`、`outline.md`、`timeline.md`、`foreshadowing.md`、`knowledge-reader.md`、`knowledge-protagonist.md`、`characters/_index.md`，以及本批出场人物的小传。
3. `read` 前 3 章正文（第一批则读 `outline.md` 的开局设计）；再读前一批细纲的最后一章，接住章末钩子。
4. 缺 bible 或缺人物小传：先回 `novel-bible`，不要凭记忆写。
5. 用 `todo_write` 列出本批每章一项，写清章号与标题。

## 二、本章开写前五问（每章都答，答案写进细纲）

在动笔写细纲前，先回答这五个问题；答不上来就说明大纲这一章是空的：

1. **出场谁**：列具体姓名，不写「众人」「几个护卫」。
2. **在哪、什么时间、什么天气**：地点要具体到院/街/舱/洞，天气要能影响行动。
3. **人物此刻的处境**：上一章结尾留下的麻烦、伤势、债务、误会。
4. **心情与身体状态**：累不累、怕不怕、饿不饿、伤在哪；这会决定他说话的长度和动作。
5. **本章行为目标**：他主动想做成的一件具体事，例如「今晚混进账房抄走那页账」，不是「查明真相」。

答案直接进 `chapter-template.md` 的「人物处境与心情」一节。五问有一条空着，先补大纲或问用户，不要用巧合填。

## 三、操作步骤：每章细纲的写法（九节填满）

每批按固定顺序做，不跳步：

1. 定本批章号与暂定标题，写进 `todo_write`；读上一批最后一章的钩子。
2. 逐章答「开写前五问」，答案先写在纸上/草稿里。
3. 按九节填 `chapter-template.md`，先填功能与冲突五段，再补环境与信息。
4. 列说话人清单，写 3–6 句关键对话与潜台词。
5. 填大纲回收清单，标出覆盖与偏离。
6. 过第九节自检清单，改完再汇报。
7. 给用户 1 页摘要，等确认；不确认不动下一批。

按 `skills/novel-setup/templates/outline/chapter-template.md` 逐节写，不留「待定」：

- **本章功能**：推进 / 转折 / 铺垫 / 回收 / 喘息；写清本章结束时局势比开章变了什么；目标字数。
- **出场人物表**：每人两列——本章想要什么、本章阻碍。必须是本章的具体欲望，不抄全书目标。
- **地点与环境**：地点、时间天气、**至少 3 个可调用的具体物象**（能拿起、打碎、闻到、听见的东西）。
- **人物处境与心情**：主角进入本章时的处境、心情与身体状态、本章行为目标——五问的答案落在这里。
- **冲突五段**：开场钩子 / 第一层阻碍 / 升级（谁逼谁做选择）/ 转折或反转 / 解决及代价。每段 2–4 句，写「谁做了什么」。
- **信息与伏笔**：读者新知 / 主角新知 / 埋设编号 / 回收编号，四行都要有内容，没有就写「无」并想清楚是否真无。
- **人物一致性**：每个出场人物一句——这个选择符合他的执念吗？不符合就写理由（被逼、伪装、成长）。
- **章末钩子**：类型（悬念 / 反转 / 情绪 / 新信息）+ 最后一句或最后一个画面。**钩子要写成「一个人想做一件事但被挡住」**，不写疑问句、不写总结句。
- **埋点写法**：伏笔只作为「当章本来就要发生的事」的一部分出现——符纸是为了镇压邪祟，铜鼎是为了镇魂，都有当章解释。**禁止把埋点写成独立桥段**（不写「她多看了一眼」「她总觉得哪里不对」），也不给特写、不停顿。细纲里要写的是「这个物件在这一章干什么用」，不是「这里埋 F00X」。
- **衔接**：下一章要接住的线、本章可能写崩的风险。

## 四、质量硬标准（不满足不交）

1. 每场戏都有「目标—阻碍—转折」；纯过场戏删掉，或明确标「喘息」并给一个情绪钩子。
2. 每章至少一次**选择**，且写出代价（失去什么、得罪谁、暴露什么）。没有选择的章是流水账。
3. 章末钩子必须具体到画面或一句话。禁止「留下悬念」「气氛骤然紧张」这类形容词。
4. 细纲里出现的伏笔编号必须在 `foreshadowing.md` 查得到，或当场新增 `F0xx`。不允许「临时伏笔」。
5. 不新增 bible 之外的重大设定（新能力、新组织、新规则）。要加先问用户，同意后先入 bible，再写细纲。

## 五、对话区分度（写关键对话前必做）

先列「本章说话人清单」：

| 人物 | 一句代表台词 | 句长 | 用词 | 口头禅 | 回避话题 |
| --- | --- | --- | --- | --- | --- |
| 沈砚 | 「账不是这么算的。」 | 短句，少超过 15 字 | 市井、带数目字 | 「说白了」 | 不提母亲 |
| 顾氏 | 「你父亲当年也这么说。」 | 长句，爱绕 | 书面、引经 | 无 | 不提那封信 |

要求：

- 代表台词遮住提示语也能认出是谁。
- 同场两人以上，标出谁先开口、谁打断、谁沉默——沉默也是说话方式。
- 细纲里的关键对话只写 3–6 句：谁说、潜台词是什么。整段对白留给正文。
- 发现所有人都「冷笑」「淡淡道」，是对话失真的信号：回小传重写「说话方式」，再写细纲。

## 六、大纲回收清单（每批一张）

在批次末尾维护一张表，逐条对应 `outline.md` 本章的关键设定：

| 大纲本章关键设定 | 细纲是否覆盖 | 落在细纲哪一节 | 偏离原因 |
| --- | --- | --- | --- |
| 主角第一次见到密信 | 是 | 冲突五段 · 转折 | — |
| 顾氏说出半句身世 | 改为只提「你父亲当年」 | 对话 | 全说是后期爆点，提前会削弱第 14 章 |

规则：覆盖不了的写「有意偏离 + 原因」，交用户确认；**不要静默丢设定**。每批汇报附这张表。

## 七、用户交互点

每批写完给 1 页摘要：每章 3 行（本章功能 / 冲突一句话 / 章末钩子），再加本批新增与回收的伏笔编号、回收清单里的偏离项。

然后 `ask_user_question` 问 1–3 个，带选项与推荐：

1. 「这 3–5 章可以开写吗？」选项：可以，开写（推荐）/ 先只写第 1 章试写 / 要调整（说明哪章）。
2. 「哪一章的冲突强度不对？」选项：都合适 / 第 X 章太弱 / 第 X 章太赶。
3. 「章末钩子要不要更狠？」选项：保持 / 加一个反转 / 换情绪钩子。

用户只批 1 章时，**只把那一章交给阶段 7**，其余标「待批」，不要顺手开写。用户要改某章：先改功能与冲突，再改钩子，不重写整批。

## 八、产出文件

- `novel-project/outline/vol-XX/ch-YYY.md`，一章一个文件，章号三位、卷号两位，例 `outline/vol-01/ch-006.md`。
- 每章文件末尾追加两节：`## 附：本章说话人清单`、`## 附：大纲回收`，不另建文件。
- 更新 `novel-project/PROJECT.md`：当前卷/章、本批细纲状态（已确认 / 待批 / 待改）、下一步。
- **给本批章节补「故事线强度」规划值**：打开 `bible/plot-map.md` 的「故事线强度」表，把这几章的 `—` 换成本章的推进程度（0 = 这条线没动，3 = 推进且有代价，5 = 本章高潮或无路可退的转折），然后在表下注明「第 N 章起为规划值」。填完跑一次 `graph-sync.mjs` 与 `render-graph.mjs`，让图跟上。

## 九、质量自检清单

- [ ] 每章九节全填，没有「待定」「TBD」「视情况」
- [ ] 五问的答案在「人物处境与心情」里都能看到
- [ ] 每场戏有目标—阻碍—转折，每章至少一次选择与代价
- [ ] 章末钩子是画面或一句话，不是形容词
- [ ] 伏笔编号在 `foreshadowing.md` 可查，或已新增
- [ ] 时间、地点、伤势与 `timeline.md` 一致，角色没有瞬移
- [ ] 说话人清单每人的代表台词可以互相区分
- [ ] 大纲回收清单覆盖本章全部关键设定，偏离有原因
- [ ] 没有 bible 之外的重大新增设定
- [ ] 本批章号连续，与上一批钩子接得上

## 十、门禁

用户确认本批后：更新 `novel-project/PROJECT.md`（阶段 7、本批范围、确认日期），加载 `novel-draft`。用户只批 1 章时，`PROJECT.md` 写「第 X 章可写，其余待批」，也只加载到那一章。

## 十一、失败 / 回退分支

- **大纲这一章本身不成立**（动机不成立、巧合太多）：不硬写细纲。回 `novel-outline` 改这一章，改完再回来；改的是大纲，先记决策日志。
- **写到一半发现前章细纲有坑**：记「待修清单」，不边写边改已确认细纲；影响本批的当场问用户。
- **用户要一次写 20 章**：说明风险（正文一改全废），建议先 3–5 章；用户坚持则先写 10 章并在 `PROJECT.md` 标「超前细纲」。
- **单章细纲超过 2 页**：删环境描写与次要人物，保留冲突五段与钩子；细纲是施工图，不是正文。
- **写盘失败或章号错**：`bash ls novel-project/outline/vol-XX/` 核对已有文件，按连续章号重命名，不覆盖已确认文件。

确认后更新 `novel-project/PROJECT.md`，加载 `novel-draft`。
