# 阶段 3 · 故事大纲

目标：产出一份能直接拆细纲的大纲——结局清楚、中点有反转、每卷有独立目标、冲突有具体载体。**本阶段不写细纲，不写章节内容。**

## 一、前置检查

- `bible/architecture.md`：核心矛盾、金手指的代价、反派的自洽理由、结局倾向。
- `bible/style.md`：已确认。至少要有叙事视角与句长规则，否则章节表会写出与文风不匹配的节奏。
- `bible/characters/*`：主角、对手、爱人或挚友的执念与缺陷。
- `PROJECT.md`：目标篇幅、分卷数、单章字数。

缺结局倾向就问；缺反派逻辑回 `novel-architecture`，**不要在大纲阶段替反派编动机**。

## 二、先定结局，不要从第一章往后推

问用户之前，自己先想清三件事，再给具体方案：

1. 最后一个画面：谁、在哪、在做什么、镜头停在哪。
2. 主角相比开局失去了什么、得到了什么（弧光的落点）。
3. 为什么是这个结局：主题上回答了什么，而不是「这样比较爽」。

用户答不出时给 3 个具体方案，每个写清代价与对前文的要求：

| 方案 | 结局画面 | 代价 | 对前文的要求 |
| --- | --- | --- | --- |
| 惨胜 | 目标达成，但身边人不在 | 失去关系 / 信念受损 | 必须提前埋「赢了也会失去」的代价 |
| 失去后释然 | 放弃执念，换回某种平静 | 放弃全书追求的东西 | 中点必须让「执念本身有问题」成立 |
| 开放式 | 停在选择发生前一秒 | 不给答案 | 最后一卷不能把矛盾收死 |

结局确定后写进 `outline.md` 第一节，一句话能说清，否则重写。

## 三、再定中点反转

中点 = 主角以为自己赢了或找到了答案，结果规则被改写。

写清四件事：

- 中点事件：一句话，含地点与对手的动作。
- 反转前主角相信什么 → 反转后相信什么。
- 这个反转如何逼出后一卷的代价。
- 主角在中点之后**不能再用的旧方法**是什么。

判断标准：中点之后主角若还能用第一幕的方法解决问题，说明中点太弱，重做。

## 四、主线三问（写进 `outline.md` 第一节）

1. **主角要什么**：具体到可以被拒绝的请求、可以被夺走的东西。不是「变强」「复仇」「活下去」。
2. **谁不让**：具体到人，且这个人有他自己认为正确的理由。
3. **为什么现在必须解决**：一个倒计时——期限、追杀、毒发、婚期、证据销毁、节庆前。

三问答不上任何一条，不要往下写分卷。三问的答案要能互相咬合：第 2 条的人，正是第 3 条倒计时的制造者。

## 五、切分 3–5 卷

每卷必须有「卷内可完成的目标」+「卷末改变全局」。五列对应模板，逐项填：

| 项 | 要求 | 反例 |
| --- | --- | --- |
| 卷目标 | 这一卷要拿到的具体东西 | 「继续成长」 |
| 主要阻碍 | 谁 / 什么在挡，且比上卷更强 | 同一个反派重复使坏 |
| 主角付出的代价 | 失去的人、暴露的秘密、破掉的底线 | 「受了点伤」 |
| 卷末高潮 | 一个不可逆的选择或事件 | 打完一架各自回家 |
| 留给下一卷的钩子 | 新信息 / 新威胁 / 新关系 | 「欲知后事如何」 |

分卷长度按 `PROJECT.md` 折算：单卷 15–40 万字，每卷 8–20 章（按单章字数换算）。不要出现 3 章一卷或一卷占全书一半。卷末高潮之间要有递进：每卷的「不可逆」必须比上卷更贵。

后续卷不拆章时，在「二、分卷」表后加一个「卷级节拍」小节：每卷 5–8 条，一句话一条，写清「谁做了什么 → 局面变成什么」。

## 六、冲突设计（七选二到三）

七种：生存与自由、个体与集体、真实与虚幻、记忆与遗忘、秩序与混乱、表象与本质、成长与代价。

规则：

- 选 **2–3 种**，每种必须写「谁和谁、在哪个事件里体现、主角必须放弃什么才能赢」。
- 不允许只写标签。检查法：把冲突类型名遮住，只看载体，还能看出是哪一种，才算成立。
- 三种冲突分层：一种贯穿全书（母题），一种管一卷，一种管一场戏。三层不能是同一件事换说法。
- 母题要能在结局被回答一次；只在开头提一提的不算母题。

| 冲突类型 | 具体载体（谁 vs 谁） | 在哪个事件 | 主角要放弃什么 |
| --- | --- | --- | --- |
| 秩序与混乱 | 主角 vs 师父所维护的门规 | 卷二 第 9 章 逐出师门 | 放弃身份与庇护 |
| 成长与代价 | 主角 vs 自己的旧誓言 | 卷三 第 4 章 救人即违约 | 放弃「干净」的自我认知 |

## 七、章节表（至少拆第一卷）

每章一行：章 / 标题 / 地点 / 核心事件 / 冲突 / 人物变化 / 埋设·回收。硬规则：

- 每章必须改变一个东西：信息、关系、处境、认知，四者至少一个。
- 每 3 章至少一次小高潮；连续 3 章无变化就是水章，合并或删。
- 埋设与回收成对登记：第 3 章埋的，注明计划第几章回收；回收不了的不要埋。
- 第一卷 8–15 章足够；超出说明事件密度不够或目标太散。
- 章节标题先不定死，可留「待定」，但事件不能留空。

## 八、节奏曲线

标出五个位置与强度（1–5），写进 `outline.md` 第五节：

| 节点 | 位置 | 强度 | 写法 |
| --- | --- | --- | --- |
| 开局 | 1–3 章 | 3 | 前 300 字给异常与欲望，不要先讲世界观 |
| 第一转折 | 约 10%–15% | 4 | 主角第一次主动行动并失败 |
| 中点 | 约 50% | 5 | 规则改写，旧方法失效 |
| 最低谷 | 约 75%–80% | 5 | 失去最重要的人 / 物 / 信念 |
| 终局 | 最后 10% | 5 | 用中点学到的代价换胜利 |

外加两条：哪几段连续高压（不超过 5 章）、哪里留 1–2 章呼吸（用关系戏或日常戏，但仍要推进信息）。呼吸章不是水章。

## 九、大纲质量自检清单

| 检查项 | 通过标准 |
| --- | --- |
| 结局可一句话说清 | 说给没看过设定的人也能懂 |
| 每卷目标可完成 | 卷内能做完，不是留给下一卷 |
| 阻碍逐卷升级 | 每卷的对手或规则比上卷更强 |
| 冲突有载体 | 遮住类型名仍能看出是哪种冲突 |
| 三问咬合 | 谁不让 = 倒计时的制造者 |
| 每章有变化 | 删掉任一章，后文会缺东西 |
| 伏笔成对 | 每条埋设都有回收章 |
| 节奏有呼吸 | 高压段不超过 5 章连续 |
| 与风格匹配 | 章节节奏不与 `style.md` 的单章结构冲突 |
| 篇幅对得上 | 章节数 × 单章字数 ≈ 目标篇幅（误差 ≤20%） |

## 十、逻辑自检（`outline.md` 第六节，逐条给答案）

- **主角为什么不报警 / 不求助 / 不逃离**：给一个具体限制——身份、证据不足、人质、时间、规则、被监视。
- **反派为什么不直接杀主角**：写清「杀了会失去什么」，不能靠「反派话多」。
- **关键巧合的前置铺垫**：每个巧合写「第几章埋过什么」，没埋过的改成因果。
- **时间线**：把关键事件按日期 / 季节排一遍，核对赶路、养伤、怀孕、科举、节庆、年龄。
- **金手指边界**：每次用金手指要付代价，且代价在关键节点真的发生一次。

发现漏洞先列给用户，**不要静默补设定**。

## 十一、用户交互点（每次 ≤3 问，逐轮推进）

1. 第一轮：结局倾向。给 3 个具体方案 + 推荐项，说明各自对前文的要求。
2. 第二轮：中点想要什么反转。给 2–3 个选项，说明各自把故事推向哪个方向、废掉主角哪种能力。
3. 第三轮：分卷切分。3 / 4 / 5 卷，各自写清节奏代价与工作量。
4. 章节表写完后问一句：「第一卷章节表现在定，还是先只到卷级节拍？」

用户全部答「你定」时，给默认方案并说明理由，但仍要用户点头再落盘。

## 十二、产出与门禁

- 产出：`novel-project/bible/outline.md`，按模板六节填满，不留占位。
- 更新 `PROJECT.md`：当前阶段 3、当前进度写「大纲 v1 已完成」、新增一行「大纲版本」，决策日志记录结局 / 中点 / 冲突类型的选择与原因。
- **同时出两张图的初版**（阶段 3 就出，不要等定稿）：

```bash
node "<技能 Base directory>/../novel-graph/tools/graph-sync.mjs" --project novel-project --init
node "<技能 Base directory>/../novel-graph/tools/render-graph.mjs" --project novel-project
```

  产出 `bible/relationship-map.md` / `plot-map.md` 和对应 `.svg`。此时只有骨架：人物来自 `characters/`，章节强度全是 `—`，**是给用户看结构用的草图，不要当成成品汇报**。
- 汇报 ≤10 行：主线一句、结局一句、中点一句、分卷表（卷名 + 卷末高潮各半句）、冲突载体、节奏风险、待确认项。图附件另说一句「人物图与情节图已出初版，随细纲与正文自动更新」。
- 门禁：用户确认主线、结局、分卷后，加载 `novel-outline-review`（阶段 4）。**不要跳过审核直接写细纲。**
- 用户只要卷级大纲时：在 `outline.md` 顶部与 `PROJECT.md` 同时写「章节表待细化（第一卷仅到卷级节拍）」，不要假装已拆章。

## 十三、失败 / 回退分支

- **结局不成立**：回第二节重定结局，再顺推中点与分卷，不要只改最后一卷。
- **用户要加一条支线 / 感情线**：先问「它改变谁的哪个选择」。不改变任何选择的支线不进大纲。
- **章节数超目标 30%**：合并功能重复的章；仍超则请用户确认调整篇幅目标，不要偷偷删事件。
- **中点想不出反转**：回 `architecture.md` 看「金手指的代价」与「反派的正确理由」，反转通常藏在这两处；仍无解就把中点降级为「重大损失」，并在报告里标注结构风险。
- **用户坚持不要审核**：记录「用户跳过阶段 4」，在 `PROJECT.md` 留痕，然后进阶段 5；但要说明细纲阶段发现结构问题会返工更多。
