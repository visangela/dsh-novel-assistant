# 阶段 −1 · 导入与重建

目标：让一本已经在写的书接进项目，而不是把它的作者送进一套空表格。**本阶段不改正文一个字**，只做四件事：认账、归一、抽取、体检。

## 一、先分清「能推断」和「必须问」

导入的本质是重建七份账本。它们的证据强度不一样，处理方式也不该一样：

| 账本 | 证据来源 | 强度 | 怎么做 |
| --- | --- | --- | --- |
| 章节清单 / 字数 / 章内结构 | 直接扫文件 | 确定 | 脚本写死，不用问 |
| `digest.md` 章节摘要 | 逐章读正文蒸馏 | 高 | 写进去，标注「导入版」 |
| `facts.md` 硬事实 | 数字 + 单位 + 上下文 | 高 | 逐条指回原句，写不出出处的进「待核」 |
| `style.md` 风格 | 句长、段长、对话占比 | 高 | 统计 + 摘 5 段样文，不问 |
| `timeline.md` 时间线 | 正文里的时间词 | 中 | 写进去，拿不准的标「待核」 |
| `characters/` 人物 | 人名频次 + 出场归纳 | 中 | 先去重再写，同一人不同称谓要合并并留证据 |
| `foreshadowing.md` 伏笔 | 反复出现的物件 + 后文是否回应 | 低 | **只收正文里明确有回应的**，其余列「疑似」 |
| `outline.md` 大纲 | 作者给 / 从正文反推 | 低 | 有就搬，没有就问，不替作者编 |

一句话规矩：**能指到原句的才写成事实，指不到的写成问题。**

## 二、五步流程

| 步 | 做什么 | 产物 |
| --- | --- | --- |
| 1 扫描 | 找章节、判章号、数字数、看缺什么 | `reviews/import/scan.md` |
| 2 归一 | 规范化副本 + 原稿留底 + 每章建 v1 存档 | `chapters/vol-01/ch-001.md`、`chapters/_original/` |
| 3 抽取 | 每 3–5 章一批读正文，写 digest / timeline / facts / 人物候选 | 四份账本的初稿 |
| 4 归并 | 人物去重、关系补边、伏笔分「已回应 / 疑似」 | `characters/`、`relationship-map.md` |
| 5 体检 | 报告 + 3–5 个必答问题，答完才写 `PROJECT.md` | `reviews/import/report.md` |

命令（第 1、2 步不调用模型，先跑这两步给用户看）：

```
node "<技能 Base directory>/tools/import-scan.mjs" <稿件目录> --write
node "<技能 Base directory>/tools/import-normalize.mjs" <稿件目录> --project <项目目录>
```

`import-normalize.mjs` 默认只打印计划，加 `--apply` 才复制、改名、建存档。**先给用户看计划表，再执行。**

第 3 步必须分批。四十章十二万字一次读不完，也不该一次读完：每批 3–5 章，只产出增量行；批次之间不回头改写上一批，最后统一由脚本查冲突（同一人两种写法、同一数字两个值）。

## 三、两个案例分开走

**案例 1：已有 chapters + outline。**

- 大纲直接搬进 `bible/outline.md`，只补「主线三问」里缺的。
- 加一步**大纲—正文对账**：逐卷列出「大纲说 X，正文写 Y」，差异要用户裁决是改大纲还是认正文。
- 对账没做完不进阶段 7。

**案例 2：只有 chapters。**

- **不自动生成大纲。**大纲是作者的意图，模型只能提假设。
- 先问两句：原本打算写几卷、大概多少章。
- 产出的是「已写部分骨架 + 三个可能走向」，让作者选一个或自己写。
- 选定之后补一次阶段 4 的大纲审核（`novel-outline-review`），再进阶段 7。

## 四、三个已定的取舍（不要再问用户）

1. **章节文件改名。**统一成 `chapters/vol-01/ch-001.md`，原文件复制到 `chapters/_original/` 留底。理由：后面所有脚本都按这个正则找章。
2. **伏笔只收有回应的。**正文里明确回收过的进 `foreshadowing.md` 正式表；反复出现但没回收的，另起一节「疑似埋点」，让作者勾选，不混进正式表。
3. **导入后直接进阶段 7。**跳过阶段 3–6；只有案例 2（大纲是反推的）要先补阶段 4 审核。

## 五、体检报告与必答问题

报告用 `<技能 Base directory>/templates/import-report.md` 的结构，一页以内，必须回答三件事：

1. **哪些是确定的**（章数、字数、章节结构）；
2. **哪些是推出来的**（人物合并、时间线、伏笔），每条都能指回章节；
3. **哪些必须作者回答**（3–5 个，超过 5 个说明抽取做得不够）。

必答问题按这个优先级挑：主线是什么（一句话）→ 主角最想要什么、最怕什么 → 已写部分里哪条线还没收 → 后面打算往哪走 → 有没有不能改的设定。

答完再写 `PROJECT.md`：当前阶段 7、当前进度「已写 N 章」、正文模型表沿用 `novel-setup` 的模板，决策日志里记一条「由 import 导入，日期，来源目录」。

## 六、门禁与失败分支

- 扫描认出 0 章：停下问用户文件在哪，不要猜。
- 章号重复或断号：列出来让用户定顺序，不自动补号。
- 同一人被拆成两个（「沈账房」「沈砚」）：合并前把两条证据都摆出来，让用户点。
- 正文里有大段对话但无引号、或整章是提纲：标「疑似非正文」，跳过抽取并说明。
- 用户只想「先看看能不能接」：只跑第 1 步，给扫描报告，不动任何文件。
