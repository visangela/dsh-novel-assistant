# 阶段 2 · 写作风格

目标：把「我想要某种味道」变成一份能直接约束句子写法的风格卡。**本阶段不写大纲、不写正文**，只产出 `bible/style.md` 与一段定调样段。

## 一、前置检查（缺项先补，不要硬写）

- `novel-project/bible/architecture.md` 已填：题材、时代、舞台、核心矛盾、结局倾向。
- `novel-project/bible/characters/` 至少有主角与核心对手两份小传，且「说话方式」一栏不是空的。
- `novel-project/PROJECT.md` 有目标读者与阅读体验（爽 / 虐 / 烧脑 / 治愈 / 震撼）。
- `novel-project/bible/style.md` 若已有内容，先 `read`，按「更新」而不是「重写」处理；把要改的节先列给用户。

缺人物小传时不要替用户编，回 `novel-architecture` 补齐；缺题材时回 `novel-workflow`。

## 二、输入清单

动笔前把这些读到手上，不要凭记忆：

1. `architecture.md` 的「时代与舞台」「核心矛盾」「结局倾向」——决定语域与情绪底色。
2. `characters/*.md` 的「说话方式」——决定对话规则，是风格卡里最容易空转的一节。
3. 用户点名的参考作者 / 作品 / 题材。三者可以同时存在，优先级：具体作品 > 作者 > 题材。
4. `PROJECT.md` 的目标读者——同一套技法写给不同读者，密度差一倍。

## 三、用户点名作者或作品时

先明确说一句（对话里说一次，`style.md` 第一节再写一次）：

> 借鉴的是技法层——视角调度、句法节奏、意象取材方式；不复制原句、独创比喻、专有名词与具体情节。

然后做六维拆解。能用模型知识就直接用；需要具体文本特征时用 `web_search` / `web_fetch` 查证，但**引用不超过一两句作为分析对象，并注明来源**，不要把原文大段搬进 `style.md`。检索不到就注明「依据模型知识，未经文本核对」。

| 维度 | 拆什么 | 落到 `style.md` |
| --- | --- | --- |
| 叙事视角与距离 | 人称、限知范围、叙述者贴多近、允不允许切视角 | 二、叙事视角 |
| 句法与节奏 | 平均句长、长短句配比、段落长度、断句与标点习惯 | 三、语言质感 |
| 词汇与比喻系统 | 用词层级（口语 / 书面 / 古雅 / 冷硬）、比喻密度、比喻取材（自然 / 器物 / 身体 / 行业） | 三、语言质感 + 七、意象 |
| 对话方式 | 对话占比、潜台词密度、说话动词、人物语言如何区分 | 四、对话规则 |
| 场景与感官描写 | 感官优先顺序、切入角度、动静比例、是否用环境投射情绪 | 五、场景与描写 |
| 章节节奏与钩子 | 单章场景数、信息释放速度、章末钩子类型 | 六、节奏与章节结构 |

拆完必须落成 **3–5 条可执行规则**，不是形容词。每条规则要能回答「下一章这句话该不该这么写」。

| 规则（可执行） | 反例 | 正例 |
| --- | --- | --- |
| 情绪不直说：删掉「愤怒 / 悲伤 / 害怕」，改用身体动作与器物反应 | 她愤怒地看着他 | 她把茶盏放回桌上，放得很轻，杯底还是磕出一声 |
| 动作段用短句，单句不超过 15 字；描写段可到 40 字 | 他一面试探着向前走一面观察着四周的动静 | 他往前走了一步。又停下。 |
| 比喻每千字不超过 3 个，且取自器物与天象，不用抽象概念 | 她的悲伤像一片无边的海 | 她的手心凉得像刚摸过井水 |

形容词式的「冷峻」「绮丽」「有古意」一律不算规则，改写成数字、动作或可判定的条件。

**取样法（避免把偶然当特征）**：取三段各 300 字——开篇、一场对话、一段高潮——分别按六维标注，只保留三段都出现的特征作为「作者稳定特征」，只出现一次的当偶然，不作为规则来源。没有原文可读时，用模型知识描述该作者的公认特征，并在 `style.md` 标注来源与不确定性。

## 四、让用户选方向（必做）

给 2–3 个方向，命名要具体，不要「文艺 / 高级 / 有质感」。每个方向配 **150–250 字同场景试写**：

- 场景固定：优先用 `architecture.md` 里已确定的真实场面（卷一开篇，或主角与核心对手第一次正面交锋）；没有可用场面时，用测试场景「雨夜，主角进了一间不该进的屋子，屋里有个人背对着他」。
- 样段里至少出现两个人、一次对话、一个具体器物；不许用旁白解释设定。
- 三个方向写同一件事、同一个信息量，只变写法，用户才能比。

无思路时按题材取默认方向，再给一个反差选项：

| 题材 | 默认方向 | 反差方向 | 常见坑 |
| --- | --- | --- | --- |
| 古言（宅斗 / 宫斗） | 冷峻克制：短句、少形容词、情绪藏在礼数与器物里 | 绵密绮丽：长句、重感官、衣饰香气层层铺 | 现代词入古、人物用现代逻辑说话 |
| 古言武侠 | 爽利口语：动作段短句、对话带江湖气 | 冷硬写意：留白多、打斗写意不写招 | 打斗像数值对轰、侠义变说教 |
| 古言官场 | 冷硬公文腔 + 私情暗涌 | 绵密世情：人情往来细写 | 权谋靠旁白解释、对手降智 |
| 仙侠 | 清冷疏阔：意象取山川云气，句中长 | 绵密绮丽：重境界铺陈与感官 | 境界设定当说明书讲、情感空转 |
| 悬疑 | 冷峻克制：短句、信息克制、感官偏冷 | 黏稠不安：长句、心理描写密 | 提前解释、靠巧合推进 |

迭代规则：**最多两轮**。第一轮三选一，或用户说「A 的句子 + B 的意象」；第二轮只针对选定方向写 1 个变体（更冷 / 更密 / 更快），不再铺第三个方向。混合时问清主次（七三开），否则容易写成四不像。

## 五、填写 `bible/style.md`

按模板九节逐项填满，不留 `{{...}}` 占位。硬要求：

- **一、参考与提炼**：写清参考对象、借了什么（结构 / 节奏 / 语言质感 / 意象体系）、明确不借什么。没有参考对象时写「无参考作品，按题材共识与本项目设定自建」，不要留空。
- **二、叙事视角**：写清「谁在场才能写什么」。限知视角下不许写主角看不到的信息；写清多久切一次视角、允许切给谁。
- **三、语言质感**：句长给数字区间；比喻密度给「每千字 X 个」；标点边界写清破折号、省略号、感叹号能不能用、用在哪。
- **四、对话规则**：每个主要人物一行——句长、用词层级、口头禅、回避的话题、代表性台词（≤20 字）。这一节是后面对话区分度的唯一依据。
- **五、场景与描写**：感官优先顺序写成序列（如「先听觉 → 再触觉 → 最后视觉」）；战斗 / 感情戏各选一种写法并说明什么时候换。
- **六、节奏**：单章字数区间、场景数、章末钩子类型轮换规则（不许连续三章同类型）。
- **七、意象**：选 3–5 个可复用意象，每个写「在什么情境出现、指向什么」；母题一句话，且必须能在结局被回答一次。
- **八、禁忌清单（AI 味）**：除模板已有四条，至少补 3 条本书特有禁忌，要具体到句式，例如「禁止用『仿佛』开头写比喻」「禁止角色在对话里解释自己的动机」「禁止章末用总结句收束」。
- **九、样段**：≤300 字，从选定方向的试写里改定。必须与规则一致——数一遍句长、比喻数、情绪词数量再落盘。

## 六、风格卡的维护方式

- 正文阶段每章开写前读一遍 `style.md`，挑 1–2 条作为本章重点；写完用这几条自检，不要每章都试图满足全部规则。
- 连续三章违反同一条规则，说明规则不合用，回来改规则，不要怪正文。
- 用户提出文风问题，先定位到具体一节（视角 / 句法 / 对话 / 描写），改规则再改文字；只改一段文字而不改规则，下次还会犯。
- 用户在正文阶段要求换文风，先评估已写章节要不要重写，给「从下一章生效 / 回改全部」两个方案及工作量。

## 七、质量自检清单

| 检查项 | 通过标准 | 怎么验 |
| --- | --- | --- |
| 规则可执行 | 随便挑一条，能判断某句合格与否 | 拿样段逐句对照，指出哪句违规 |
| 规则不打架 | 「短句为主」与「绵密长句」不能同时出现 | 通读第二节到第六节 |
| 人物语言有区分 | 去掉说话人也能猜出是谁 | 抽三句台词做盲测 |
| 样段合规 | 句长、比喻密度、情绪词数与规则一致 | 手工计数 |
| 与题材匹配 | 古言无现代词；悬疑不提前解释 | `grep` 样段里的可疑词 |
| 与架构一致 | 人称、视角限制不与 `architecture.md` 冲突 | 交叉读两份文件 |
| 禁忌可检索 | 每条都能在正文里 `grep` 出来 | 逐条想一个检索词 |

## 八、用户交互点

- 第一问：方向选择。选项：A 方向 / B 方向 / C 方向 / 混合（说明比例）/ 都不像，说哪里不像。推荐项写在最前并说明理由（与题材、主角性格、目标读者的匹配度）。
- 第二问：选定向后只问一处——「哪一条规则要改硬 / 改软」。
- 第三问：定稿前问「样段就按这版定，还是再改一版」。每次最多 3 问，一次问完，不要边写边追问。

## 九、产出与门禁

- 产出：`novel-project/bible/style.md`（九节填满 + 样段）。
- 汇报 ≤8 行：选定方向、3–5 条核心规则各一句、样段字数、与架构的冲突点（若有）、待确认项。
- 门禁：用户说「可以 / 定稿 / 就这个」后，更新 `PROJECT.md`——阶段改为 3、记录「风格方向」「style.md 版本 v1」、决策日志写一行选择与原因，然后加载 `novel-outline`。**未确认不要进入阶段 3。**

## 十、失败 / 回退分支

- **用户说不出想要什么**：不要追问形容词。用题材默认方向表给两个具体方向 + 一个反差，直接上样段让用户选。
- **用户嫌样段「不像」**：追问不像在哪——句子太长 / 太文 / 太现代 / 人物说话太像 / 没有画面。按维度改一节，不要整段重写。
- **用户要求「一模一样」**：说明只能借技法，给出「技法清单 + 本项目改写」，拒绝逐句模仿；用户坚持则在 `style.md` 记「用户要求高度接近，已提示风险」。
- **两轮后仍不满意**：停止试写，落一版最小风格卡（视角 + 句长 + 对话三条），在 `PROJECT.md` 标「风格待正文验证」，进入阶段 3。不要无限试写消耗用户耐心。
- **与架构冲突**（例如架构定第一人称，风格卡要全知）：不要自己改，把冲突列出来让用户选，改哪边都要在决策日志留痕。
