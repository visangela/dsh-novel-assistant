# 代笔交接单 · 第 N 章

> 用法：主代理填好整份，L1 直接作为 `subagent` 提示词，L2 落成 `prompt.md` 交给用户粘贴。
> 写成「给一个看不到这个项目的作者」看的：路径换成人话，别让对方猜。

## 一、你是谁

你替一部长篇小说写第 N 章正文。这本小说的叙事语感如下（摘自风格指导书第九节样段）：

```text
<贴 200–300 字样段原文，不要转述>
```

三条不许破的写法：

```text
1. <视角与人称，例如「第三人称限知，全程贴沈砚，不写他看不见的东西」>
2. <句式特征，例如「短句为主，一段不超过四句；不用破折号插入语」>
3. <对话规则，例如「提示语只用『说』；情绪靠动作，不靠副词」>
```

## 二、你必须先读的文件（本机绝对路径或项目相对路径）

```text
novel-project/bible/style.md              ← 重点第八节禁忌清单、第九节样段
novel-project/outline/vol-XX/ch-YYY.md    ← 本章细纲，九节全读
novel-project/bible/timeline.md           ← 本章对应行
novel-project/bible/digest.md             ← 最近 3 章摘要 + 按 F 编号查到的旧章（见附录）
novel-project/bible/facts.md              ← 度量、账目、纪年、路程口径（有数字就对一遍）
novel-project/bible/characters/<name>.md  ← 每个出场人物：执念 / 说话方式 / 压力下的反应
novel-project/chapters/vol-XX/ch-<N-1>.md ← 只读最后 300 字，接住钩子
```

## 三、本章要写什么

```text
一句话：<谁想要什么，被什么挡住>

必须发生（3 条以内）：
1. …
2. …
3. …

必须埋 / 必须收的伏笔：<F0xx 埋 / F0xx 收>

本章不能发生：<不能提前揭的底、不能出现的人物、不能用的能力>
```

## 四、硬约束

```text
字数：2000–4000 字（正文，不含注释）
开头：第一行必须是「# 第 N 章 标题」
结尾：落在动作、画面或没答完的话上；不写总结、不写「欲知后事如何」
禁用：排比堆砌、段末升华、角色替作者讲道理、「不是……而是……」连用
必须：至少 3 个可触摸的物象；至少 1 处「说的和想的不一样」的对话

可核对事实（数字、度量换算、账目、价格、纪年、路程、器物规格）：
只能取自 bible/facts.md 与本章细纲。表里没有、又非写不可的，写〔待定：用途〕，不要自己编一个看似合理的数。
不许换口径：同一件事全书只用一套算法（例：吃水 = 空船吃水 + 石数 ÷ 100 × 每百石下沉）。
```

## 五、输出格式（两种通道要求不同，填单时二选一，删掉另一段）

**L1 自动代笔**——你是本机上的 agent，有写文件的工具：

```text
把正文直接写进 novel-project/chapters/vol-XX/ch-YYY.md，从「# 第 N 章 标题」开始。
末尾追加 HTML 注释块「本章新增事实」，格式照 novel-draft 第五节的模板，只写事实与还没写进设定库的条目，不写剧情摘要。
除这个文件外不要动任何东西：不改 bible、不改 PROJECT.md、不碰别的章节。
正文里不许留代码围栏、不许留提纲句子、不许写创作说明。
```

**L2 手动代笔**——你在用户的外部工具里，只有对话框：

```text
只输出正文 markdown，从「# 第 N 章 标题」开始。
不要解释、不要写创作说明、不要加代码围栏、不要写「本章新增事实」注释块（这个由主代理补）。
```

## 六、交稿前自检（自己过一遍，不要交完再改）

```text
1. 有没有出现设定里没有的人名、地名、组织、能力？
2. 时间线接得上上一章最后一句吗？有没有瞬移、伤势隔夜痊愈？
3. 有没有替读者解释情绪、解释意义？
4. 有没有连续两段以上用同一个句式开头？
5. 结尾删掉最后一句，本章会变平吗？会变平说明钩子无效。
6. 本章每个数字/度量，都能在 bible/facts.md 里找到出处吗？找不到的有没有写成〔待定：…〕？
7. 附录里给了原句的伏笔，你有没有换掉那个物象？（核桃的银丝、算盘的暗刻、袖口的墨渍）回收时先让读者认出它，再解释它是什么。
```

## 七、回填与验收（主代理用，L2 时附在 prompt 末尾）

```text
回填路径：novel-project/chapters/vol-XX/ch-YYY.md
验收命令：node <技能 Base directory>/tools/check-chapter.mjs <该路径> --min 2000 --max 4000 --bible novel-project/bible
不看解释、不看自评，只看文件：字数在区间、无残留标记、人名都在设定库里。
不通过就退回重写该段，本章不计入章数。
```

## 八、附录：上下文包（主代理用 `context-pack.mjs` 生成后整段贴进来）

```text
<把 node tools/context-pack.mjs <章号> 的输出原样贴在这里：必读文件、本章伏笔原句、最近章节摘要、上一章末尾>

规矩：
1. 「原句」是既成事实，物象、动作、数字、语气都不许改。你要做的是让读者认出它，不是重写它。
2. 「上一章末尾」只用来接语气和钩子，不要复述上一章的剧情。
3. 摘要行里没写的事，就是这本书没发生过的事；想加新事，先问主代理。
```
